# 排错

## 授权类

**invalid_client / redirect_uri_mismatch**
重定向 URI 与扩展 ID 不匹配。打开设置页复制"重定向 URI"，与 Google 控制台里逐字符比对（末尾不能有斜杠）。

**access_denied**
账号不在测试用户列表里，或同意屏幕里没勾 Drive 权限。

**AUTH_REQUIRED**
token 过期且没有 refresh_token（隐式模式常见）。重新点"连接 Google 账号"，或改用 PKCE 模式。

**ego(lite) 里 chrome.identity 未定义**
用"手动 token"模式，见 docs/DEPLOY.md 的 C-5。

## 同步类

**"云端暂无同步文档，使用本机书签初始化"**
第一次同步的正常行为：把本机树整体推上去。**注意**：此时如果另一台设备也已经初始化过，后者会覆盖前者。正确顺序是：一台设备先初始化 → 另一台直接"立即同步"拉取。

**一直"跳过：距上次同步 X 秒"**
自动同步有 minIntervalMs（默认 30 秒）节流。手动点"立即同步"不受限。

**"等待确认删除操作"**
单轮删除数超过阈值。弹窗里会列出清单，确认无误点"确认删除并同步"。

**两边一直互相覆盖同一个标题**
检查是否两台设备的系统时间差很大（LWW 依赖时间戳）。可把"字段冲突"改成"总是保留本机 / 云端"固定一侧。

**书签突然全部变成两份（每个文件夹里都有一模一样的两套）**
新设备接入已有云端文档时 nodeId 对不上导致的历史问题，v1.2.5 已用「身份对齐」根治。
已经翻倍的：设置页 → 5. 云端文档健康 → **按内容去重**，然后重新同步。
详见 docs/CORRUPT-DOC.md 第四节后半部分。

**同步被拦下，提示「id 重合 0% 但内容重合 100%」**
这是重复副本护栏在保护你的云端，不是故障。说明本机与云端用的是两套 nodeId，
先执行「按内容去重」，再「立即同步」。

**同步完成但某条书签没同步过去**
该节点可能被"跳过文件夹标题"过滤了。检查设置里的排除列表（精确匹配标题，会连带整棵子树）。

## 数据类

**误删了书签**
设置页 → 历史快照 → 找到删除前的快照 → **合并恢复**（只补回缺失的，不删现有）。若只是想拿回那几条，也可以直接看快照 JSON 里 deleted: true 的项。

**云端文档坏了 / 想重来**
设置页 → "重置同步基线"（不删任何书签，只丢弃 base，下次全量重新比较）。

**清除扩展数据**
chrome://extensions → 本扩展 → "移除"会清掉 IndexedDB 与 storage（云端文件不受影响）。

## 性能类

**首次同步很慢**
全量扫描 + 全量上传。1 万条书签约 1–3 秒，属正常。之后都是增量。

**Service Worker 频繁被杀**
MV3 正常行为。所有状态都在 IndexedDB / storage，被杀不影响正确性；定时任务由 chrome.alarms 接管。

## 自检对照表

| 检查项 | 失败意味着 |
| --- | --- |
| chrome.bookmarks | 该浏览器不支持书签 API，无法使用 |
| chrome.storage | 无法保存设置 |
| chrome.alarms | 自动同步退化为纯事件触发 |
| chrome.identity | 只能用手动 token 模式 |
| bookmarks 事件 | 只能靠定时同步 |
| 读取书签树 | 权限未授予，或书签 API 受限 |
| 写入书签 | 只读数据集（企业策略），无法落地变更 |
| OAuth Client ID | 还没配置，无法授权 |
| Drive appDataFolder | token 无效或没勾 drive.appdata |
